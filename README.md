qdhhc 专用，可根据个人及学校情况二开。本项目不鼓励同学们恶意预约，只是帮助同学们省去每天手动预约图书馆的重复操作。

本项目是一个本地运行的网站，用来配置图书馆座位预约任务。它会在每天设定的时间启动一次正常预约流程，读取官网可视化座位图中的真实 `devId`，然后通过官网预约接口提交，并在页面中记录任务与日志。


## 功能

- 默认每天固定时间自动开始抢座，也可以自定义每周的周几执行；开始抢座时间只需要设置小时和分钟。
- 支持一个主座位和两个备选座位：主座位失败后依次尝试备选 1、备选 2。
- 支持多个预约时间段；每段最长 3 小时，多个时间段共用同一组候选座位。
- 选择预约开始时间后，结束时间会自动填为 3 小时后，仍然可以手动修改。
- 循环任务会按“预约日期与开始抢座日期的相对天数”滚动。
- 创建任务时可以填写任务名称；不填写时会自动命名为“任务1”“任务2”“任务3”。
- 任务列表支持立即执行、暂停/恢复执行和一键删除。
- 任务日志刷新页面后仍会恢复显示，也可以在页面中手动清空。
- ！内置系统账号登录；账号只能由管理员命令生成，不提供自行注册入口。！
- 一个系统账号只能绑定一个学号，绑定后不能修改。
- 提供独立可视化账号管理页：访问 `/admin` 后用预设管理员账号密码登录，可以生成账号、查看初始密码、查看绑定学号并一键删除。

## 运行

### 本地运行

```bash
npm install
npm run install-browsers
npm start
```

打开：

```text
http://localhost:3000
```

管理员页面：

```text
http://localhost:3000/admin
```

### Docker 部署

服务器推荐使用 Docker 部署。镜像基于 Playwright 官方镜像，已经包含 Chromium 和运行依赖。

```bash
git clone https://github.com/WanchaDJ/book.git
cd book
docker compose up -d --build
```

打开：

```text
http://服务器IP:3000
```

管理员页面：

```text
http://服务器IP:3000/admin
```

查看日志：

```bash
docker compose logs -f
```

生成一个可登录本系统的账号：

```bash
docker compose exec library-seat-reserver npm run create-user -- 用户名
```

命令会输出随机密码。用户第一次登录后需要绑定学号，绑定后不能修改。

也可以访问 `/admin`，用 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 登录后可视化生成账号、查看账号密码和绑定学号。

停止服务：

```bash
docker compose down
```

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 网站监听端口 |
| `NODE_ENV` | `development` | Docker 中为 `production` |
| `FORCE_HEADLESS` | `false` | 设为 `true` 后强制无头浏览器运行，服务器部署必须开启 |
| `TZ` | 系统时区 | 建议设为 `Asia/Shanghai`，保证每日定时按北京时间计算 |
| `DATA_DIR` | `./data` | 系统账号和任务数据保存目录 |
| `SESSION_SECRET` | 随机值 | 登录 Cookie 签名密钥，服务器部署建议固定成一串随机字符 |
| `ADMIN_USERNAME` | 空 | `/admin` 管理员账号；不设置时网页账号管理不可用 |
| `ADMIN_PASSWORD` | 空 | `/admin` 管理员密码；不设置时网页账号管理不可用 |

服务器部署时请保持 `FORCE_HEADLESS=true`。此时页面中的“执行时显示浏览器窗口”选项会被忽略，预约流程会使用无头 Chromium 运行。

## 使用方式

1. 管理员先用 `npm run create-user -- 用户名` 生成系统账号。
2. 如果配置了 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，也可以访问 `/admin`，登录后生成账号，并查看账号、初始密码、绑定学号。
3. 用户用系统账号登录本工具。
4. 第一次登录后绑定自己的图书馆学号；一个系统账号只能绑定一个学号，绑定后不能修改。
5. 输入统一身份认证密码。
6. 选择开始抢座时间、执行规则、阅览区、座位号。执行规则默认是“每日执行”；也可以选择“自定义每周执行”，再勾选周几。
7. 如有需要，填写两个备选座位。预约时会按“主座位 -> 备选座位 1 -> 备选座位 2”的顺序尝试。
8. 添加一个或多个预约时间段。单段最长 3 小时。日期默认填为下一次开始抢座日期的第二天，也可以手动修改；实际预约按页面里选择的日期提交。
9. 点击“检查座位匹配”可以确认填写的座位号是否能在官网座位图中匹配到真实座位。
10. 可选填写任务名称；不填写时系统会自动生成任务名。
11. 点击“创建定时任务”。

执行时会打开 Chromium 完成正常登录，然后读取官网可视化座位图接口中的真实座位 `devId`，再调用官网预约提交接口。提交时会使用官网登录会话里的 `userInfo.accNo` 作为官网要求的 `appAccNo` / `resvMember`，同时先校验它和系统账号绑定的学号一致。遇到验证码、滑块、二次确认或接口限制时，任务会停止并写入日志，不会自动识别验证码。

## 预约规则

- 到达设定的开始抢座时间后，系统会逐个处理预约时间段。默认每日执行；如果选择自定义每周执行，只会在勾选的周几执行。
- 对于每个时间段，系统会先尝试主座位；如果失败，再尝试备选座位 1；如果仍失败，再尝试备选座位 2。
- 某个候选座位预约成功后，会进入下一个预约时间段。
- 如果某个时间段的所有候选座位都失败，该任务本次执行会失败并写入日志。
- 页面里的预约日期就是实际提交给官网的日期，不会在后端额外加一天。
- 页面不能随意填写预约学号；后端会先使用当前系统账号绑定的学号校验官网登录身份。
- 预约提交使用官网会话中的 `accNo` 字段，并要求它与绑定学号一致；如果浏览器旧会话拿到其他学号，会中止任务并写入日志。
- 循环执行时，系统会保持预约日期与开始抢座日期的相对天数。例如下一次 5 月 30 日执行且预约 5 月 31 日，下一次执行会继续预约“执行日的第二天”。

## 常见问题

### 日志显示“请求参数错误”

如果日志中先显示“找到座位 ... devId=...”，说明座位识别已经成功，失败发生在官网最终提交预约接口。常见原因包括：

- 预约日期或时间段不在官网开放预约范围内。
- 预约时间段超过官网当前区域规则，例如时间不在开放时段内、短于最短预约时间或长于最长预约时间。
- 当前账号当天已有冲突预约，官网拒绝新的时间段。
- 官网接口规则临时变化。

新版日志会在失败时附带提交摘要，包括 `appAccNo`、`resvDev`、`resvBeginTime`、`resvEndTime`。排查时先确认摘要里的账号、座位 `devId` 和预约时间是否正确。

## 任务管理

- “立即执行”会立刻按当前任务配置执行一次。
- “暂停执行”会取消该任务的下一次定时器，但任务仍保留在任务栏里；点击“恢复执行”后会按任务的每日/每周规则重新安排下一次执行。
- 红色垃圾桶按钮会删除任务，并清除该任务的定时器。
- 任务会保存到 `DATA_DIR/tasks.json`，Docker 部署会通过 `./data:/app/data` 挂载保留；更新或重启服务后会自动恢复并重新安排下一次执行。
- 日志保存在当前任务对象里，刷新网页后会重新显示；点击“清空日志”会清除当前账号所有任务的日志。
- 系统账号和绑定学号保存在 `DATA_DIR/users.json`。Docker 部署会把 `./data` 挂载到容器内，避免重建容器后丢失账号和任务。
- `/admin` 账号管理页支持删除账号。删除账号会同时清除该账号当前进程里的定时任务。
- 命令行和网页新生成的账号会保存初始密码用于管理页查看；旧版本已存在账号没有初始密码记录时会显示“旧账号无记录”。

## 安全说明

- 预约任务里的统一认证密码会加密保存到 `DATA_DIR/tasks.json`，用于服务重启后继续自动执行任务；加密密钥来自 `SESSION_SECRET`。
- 页面不会自动清空密码输入框，方便继续检查座位或创建新任务。
- 生产环境不要修改已经在用的 `SESSION_SECRET`，否则已保存任务里的统一认证密码会无法解密，需要重新创建任务。
- 不要把真实账号、密码、Cookie 或 token 提交到仓库。
- 生产环境请修改 `SESSION_SECRET`，不要使用示例值。
- 生产环境请修改 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，不要使用示例值；不要把管理员账号密码发给普通用户。
- 服务器部署时建议只绑定可信网络，或在 Nginx / 宝塔 / 反向代理层增加访问密码，不要把页面裸露到公网。
- 本项目不做验证码识别、滑块绕过、接口绕过或高频重试。
- 本项目是本地辅助工具，最终预约结果请以官网预约记录为准。
