# 图书馆座位预约助手

qdhhc 专用，可根据个人情况二开。本项目不鼓励恶意预约，只是帮助同学省去每天手动预约图书馆的重复操作。

本项目是一个本地运行的网站，用来配置图书馆座位预约任务。它会在每天设定的时间启动一次正常预约流程，读取官网可视化座位图中的真实 `devId`，然后通过官网预约接口提交，并在页面中记录任务与日志。

目标网站：

```text
https://tsgzw1.qdhhc.edu.cn/mobile.html#/ic/reserveList
```

## 功能

- 每天固定时间自动开始抢座，只需要设置小时和分钟。
- 支持一个主座位和两个备选座位：主座位失败后依次尝试备选 1、备选 2。
- 支持多个预约时间段；每段最长 3 小时，多个时间段共用同一组候选座位。
- 选择预约开始时间后，结束时间会自动填为 3 小时后，仍然可以手动修改。
- 预约日期默认填为“下一次开始抢座日期的第二天”，也可以手动修改。
- 每日循环任务会按“预约日期与开始抢座日期的相对天数”滚动。
- 支持检查座位匹配，不会提交预约。
- 任务列表支持立即执行和一键删除。

## 运行

### 本地运行

```bash
npm install
npm run install-browsers
npm start
```

打开：

```text
http://localhost:3000
```

### Docker 部署

服务器推荐使用 Docker 部署。镜像基于 Playwright 官方镜像，已经包含 Chromium 和运行依赖。

```bash
git clone https://github.com/WanchaDJ/book.git
cd book
docker compose up -d --build
```

打开：

```text
http://服务器IP:3000
```

查看日志：

```bash
docker compose logs -f
```

停止服务：

```bash
docker compose down
```

### 普通 Node 部署

如果不使用 Docker，需要服务器已安装 Node.js 20+，并安装 Playwright 的 Chromium 及系统依赖。

```bash
git clone https://github.com/WanchaDJ/book.git
cd book
npm ci --omit=dev
npx playwright install --with-deps chromium
FORCE_HEADLESS=true TZ=Asia/Shanghai npm start
```

可以用 PM2 常驻运行：

```bash
npm install -g pm2
FORCE_HEADLESS=true TZ=Asia/Shanghai pm2 start server.js --name library-seat-reserver
pm2 save
```

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 网站监听端口 |
| `NODE_ENV` | `development` | Docker 中为 `production` |
| `FORCE_HEADLESS` | `false` | 设为 `true` 后强制无头浏览器运行，服务器部署必须开启 |
| `TZ` | 系统时区 | 建议设为 `Asia/Shanghai`，保证每日定时按北京时间计算 |

服务器部署时请保持 `FORCE_HEADLESS=true`。此时页面中的“执行时显示浏览器窗口”选项会被忽略，预约流程会使用无头 Chromium 运行。

## 使用方式

1. 输入统一身份认证账号、密码。
2. 选择每天固定的开始抢座时间、阅览区、座位号。开始抢座时间只需要小时和分钟，系统会每天按该时间执行。
3. 如有需要，填写两个备选座位。预约时会按“主座位 -> 备选座位 1 -> 备选座位 2”的顺序尝试。
4. 添加一个或多个预约时间段。单段最长 3 小时。日期默认填为下一次开始抢座日期的第二天，也可以手动修改；实际预约按页面里选择的日期提交。
5. 点击“检查座位匹配”可以确认填写的座位号是否能在官网座位图中匹配到真实座位。
6. 点击“创建定时任务”。

执行时会打开 Chromium 完成正常登录，然后读取官网可视化座位图接口中的真实座位 `devId`，再调用官网预约提交接口。遇到验证码、滑块、二次确认或接口限制时，任务会停止并写入日志，不会自动识别验证码。

## 预约规则

- 到达每天设定的开始抢座时间后，系统会逐个处理预约时间段。
- 对于每个时间段，系统会先尝试主座位；如果失败，再尝试备选座位 1；如果仍失败，再尝试备选座位 2。
- 某个候选座位预约成功后，会进入下一个预约时间段。
- 如果某个时间段的所有候选座位都失败，该任务本次执行会失败并写入日志。
- 页面里的预约日期就是实际提交给官网的日期，不会在后端额外加一天。
- 每日循环时，系统会保持预约日期与开始抢座日期的相对天数。例如下一次 5 月 30 日执行且预约 5 月 31 日，下一天执行时会自动预约 6 月 1 日。

## 任务管理

- “立即执行”会立刻按当前任务配置执行一次。
- 红色垃圾桶按钮会删除任务，并清除该任务的定时器。
- 任务只保存在当前 Node 进程内，重启服务后需要重新创建任务。

## 安全说明

- 密码只保存在当前 Node 进程内，页面不会自动清空密码输入框，方便继续检查座位或创建新任务。
- 不要把真实账号、密码、Cookie 或 token 提交到仓库。
- 服务器部署时建议只绑定可信网络，或在 Nginx / 宝塔 / 反向代理层增加访问密码，不要把页面裸露到公网。
- 本项目不做验证码识别、滑块绕过、接口绕过或高频重试。
- 本项目是本地辅助工具，最终预约结果请以官网预约记录为准。
